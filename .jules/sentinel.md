## 2024-05-24 - [IDOR in Post Creation and Missing Route Authentication]
**Vulnerability:** The `POST /api/posts` and `POST /api/posts/:id/react` endpoints lacked authentication middleware in the routes definition. Furthermore, the `createPost` controller implicitly trusted `req.body.userId`, allowing any user to potentially create posts masquerading as someone else (IDOR).
**Learning:** Controller logic alone is insufficient if the middleware protecting it is missing from the route. User-supplied identification data (like `userId` in the body) should never be trusted for actions linked to the authenticated user.
**Prevention:** Always verify that routes defining state-changing endpoints (POST, PUT, DELETE) have authentication middleware applied. Within controllers, always rely on `req.user.id` (set by the authentication middleware) to determine the user performing the action, rather than relying on the client to send a `userId`.
## 2024-05-24 - [PII Exposure in Public API Endpoints]
**Vulnerability:** The `GET /api/posts` and `GET /api/users/search` endpoints inadvertently leaked user email addresses by including `email` in the `attributes` array of Sequelize queries. This exposed sensitive Personally Identifiable Information (PII) to any user, including unauthenticated ones via the search endpoint.
**Learning:** Returning entire model rows or broadly scoped `attributes` arrays without explicitly excluding sensitive fields easily leads to data leakage. The `include` directive in ORMs like Sequelize will fetch all columns by default or include whatever is specified, requiring explicit filtering.
**Prevention:** Always define explicit, minimal allowlists for attributes returned in API responses, especially when querying User models. Sensitive fields like `email`, `password_hash`, or reset tokens should never be included in default queries unless specifically required by a protected endpoint intended for the user owning that data.
