## 2024-05-24 - [IDOR in Post Creation and Missing Route Authentication]
**Vulnerability:** The `POST /api/posts` and `POST /api/posts/:id/react` endpoints lacked authentication middleware in the routes definition. Furthermore, the `createPost` controller implicitly trusted `req.body.userId`, allowing any user to potentially create posts masquerading as someone else (IDOR).
**Learning:** Controller logic alone is insufficient if the middleware protecting it is missing from the route. User-supplied identification data (like `userId` in the body) should never be trusted for actions linked to the authenticated user.
**Prevention:** Always verify that routes defining state-changing endpoints (POST, PUT, DELETE) have authentication middleware applied. Within controllers, always rely on `req.user.id` (set by the authentication middleware) to determine the user performing the action, rather than relying on the client to send a `userId`.
## 2024-06-04 - [PII Exposure via Unauthenticated Express Routes]
**Vulnerability:** The `/api/users/search` endpoint was publicly accessible and returned PII (User Emails & Display Names) because it lacked the `authenticateToken` middleware.
**Learning:** In Express, routes are public by default unless specifically protected by middleware. Even if other endpoints in a router (or the app) use auth, new endpoints might silently expose data if middleware isn't explicitly applied to them or the router. Additionally, the auth middleware was using `decoded.userId` but tokens were signed with `{ id }`, causing auth to fail securely but incorrectly, highlighting the need to verify JWT payload structures between signing and verifying functions.
**Prevention:** Always explicitly apply authentication middleware to routes returning PII. When writing JWT logic, ensure the payload keys matched between `jwt.sign()` and the properties accessed from `jwt.verify()`. Create automated integration tests for unauthenticated scenarios on all sensitive endpoints.
