## 2024-05-24 - [IDOR in Post Creation and Missing Route Authentication]
**Vulnerability:** The `POST /api/posts` and `POST /api/posts/:id/react` endpoints lacked authentication middleware in the routes definition. Furthermore, the `createPost` controller implicitly trusted `req.body.userId`, allowing any user to potentially create posts masquerading as someone else (IDOR).
**Learning:** Controller logic alone is insufficient if the middleware protecting it is missing from the route. User-supplied identification data (like `userId` in the body) should never be trusted for actions linked to the authenticated user.
**Prevention:** Always verify that routes defining state-changing endpoints (POST, PUT, DELETE) have authentication middleware applied. Within controllers, always rely on `req.user.id` (set by the authentication middleware) to determine the user performing the action, rather than relying on the client to send a `userId`.
## 2024-05-24 - [PII and Stack Trace Exposure in API Controllers]
**Vulnerability:** The API controllers (`user.controller.js` and `post.controller.js`) were returning the `email` attribute of users when populating or retrieving public data. Furthermore, `catch (error)` blocks returned `error.message` to clients directly, exposing database structures and inner application errors to end users (stack trace / internal info leak).
**Learning:** Returning `error.message` directly in 500 responses creates an information leakage vulnerability, especially in combination with Object-Relational Mappers like Sequelize which can include table column names or constraint validation details in their error structures. Additionally, returning models directly can leak Private Information like `email` unless fields are explicitly scoped.
**Prevention:** Always scope down returned fields using the `attributes` parameter on queries when joining with User models. Implement global error handlers or use static error strings for 500 errors to prevent application internals from being broadcasted to external clients.
