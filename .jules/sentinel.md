## 2024-05-24 - [IDOR in Post Creation and Missing Route Authentication]
**Vulnerability:** The `POST /api/posts` and `POST /api/posts/:id/react` endpoints lacked authentication middleware in the routes definition. Furthermore, the `createPost` controller implicitly trusted `req.body.userId`, allowing any user to potentially create posts masquerading as someone else (IDOR).
**Learning:** Controller logic alone is insufficient if the middleware protecting it is missing from the route. User-supplied identification data (like `userId` in the body) should never be trusted for actions linked to the authenticated user.
**Prevention:** Always verify that routes defining state-changing endpoints (POST, PUT, DELETE) have authentication middleware applied. Within controllers, always rely on `req.user.id` (set by the authentication middleware) to determine the user performing the action, rather than relying on the client to send a `userId`.

## 2024-05-15 - [Critical Hardcoded JWT Secret & Missing Secret Checks]
**Vulnerability:** A hardcoded `JWT_SECRET` (`'your-super-secret-jwt-key-change-in-production'`) was used as a fallback in `backend/src/middleware/auth.middleware.js`. Additionally, the token decoding relied on `decoded.userId` but the tokens were signed with `{ id }` in `backend/src/services/auth.service.js`, causing user lookup to fail gracefully without explicit error due to Sequelize's `User.findByPk(undefined)` behavior, which was masked by the lack of strict testing around authentication failures.
**Learning:** Hardcoding a default secret ensures the app silently runs in production but introduces a critical vulnerability where any attacker can forge a valid token for any user (or admin) using the default key if the environment variable `JWT_SECRET` is missing. The payload extraction bug also highlights the need for end-to-end integration tests that verify authenticated endpoints work correctly rather than just returning 200/401 indiscriminately.
**Prevention:** Remove fallback secrets. Use strict environment variable validation on startup (e.g., throwing an error if `JWT_SECRET` is missing) so the application fails fast and securely in production environments instead of adopting an insecure state. Always use variables derived from token payloads explicitly, and write tests to hit authenticated endpoints.
